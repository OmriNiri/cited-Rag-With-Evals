## Phase 0 — Setup — `chore/project-setup`

**Goal:** an empty but runnable, linted, CI-checked NestJS project with a database.

- NestJS 12 + TypeScript (`strict: true`) on Node 24
- oxlint + Prettier, Vitest (see D8, D9)
- `docker-compose.yml`: PostgreSQL 16 with `pgvector` (pinned image, healthcheck)
- `.env.example` + startup env validation; shared `pg` pool; `GET /health`
- GitHub Actions: lint, format check, build, scripts type-check, unit tests
- MIT `LICENSE`
- Corpus: Code of Obligations Art. 319–343 (English), generated by `npm run corpus:build`, with `corpus/SOURCES.md`

**Done when:** `docker compose up -d && npm install && npm run build` works from a fresh clone and CI is green. ✅ Verified: clean-clone CI simulation, CI green on GitHub, `/health` returns 200 with the database up and 503 with it down.

## Phase 1 — Ingestion — `feat/ingestion`

**Goal:** the corpus is chunked, embedded and stored in PostgreSQL.

- Loader + parser: `corpus/*.txt` (SOURCES.md excluded) → articles with their heading path
- Chunker (pure function): one article per chunk when it fits; long articles split at paragraphs → list items → sentences with short-paragraph overlap; ≤ 250 tokens of the real model tokenizer (D7). Each chunk keeps `document`, `section`, `article`, `position`
- Embedder: `Embedder` interface + local `Xenova/all-MiniLM-L6-v2` (384 dims), embedding `section + article + text` (D13)
- `chunks` table (`schema.sql`, idempotent) with HNSW (vector) and GIN (full text) indexes
- Idempotent: each document replaced in one transaction (D14); readable deterministic ids (D16)
- `npm run ingest` CLI (Nest without a web server)
- Tests: 24 unit tests (parser, splitter, chunker, ids, loader); 6 integration tests against real Postgres in a temporary schema (D15): full pipeline, run-twice idempotency, shrinking document, rollback, clean connection after failure. CI runs them with a Postgres service.

**Done when:** `npm run ingest` fills the table, running it twice gives the same row count, and the tests pass. ✅ Verified: 91 articles → 99 chunks (max 234 tokens), identical rows after a second run, unit + integration tests green locally and in CI.

## Phase 2 — Retrieval — `feat/retrieval`

**Goal:** three retrievers behind one interface.

- `Retriever` interface + `RETRIEVERS` registry (`vector`, `keyword`, `hybrid`)
- Vector: question embedded with the same model, cosine distance via pgvector
- Keyword: Postgres full-text search with OR between words, ranked by `ts_rank` (D17; AND matched 0 of 99 chunks for a natural question)
- Hybrid: RRF (k = 60) over the top 20 of each, a 20-line pure function (D18)
- Optional `document` filter (D20); separate read/write interfaces (D19)
- `npm run search -- "<question>" --mode vector|keyword|hybrid|all`
- Tests: 7 RRF unit tests with hand-made rankings, hybrid/vector retriever unit tests with fakes, CLI argument tests; 8 search integration tests with hand-made vectors and texts (ranking, exact similarity scores, OR, stemming, heading match, filter, stop-word query)

**Done when:** a CLI command returns the top-k chunks for a question with each retriever. ✅ Verified on the real corpus. Early observation recorded as a hypothesis for Phase 4 (D18): keyword search is strong with legal wording, weak with casual wording; hybrid helps only when both lists carry signal.

## Phase 3 — Answering — `feat/answering`

**Goal:** `POST /ask` returns a cited answer, or refuses.

- `LlmClient` interface, implemented by an OpenAI-compatible HTTP client (local Ollama by default); LLM settings validated by `LlmModule` only (D22)
- Model chosen by comparing `llama3.1:8b` and `qwen3:8b` on 10 questions through the real pipeline → `llama3.1:8b` (D26)
- Prompt: numbered passages; answer only from them; cite passage numbers, which code maps to chunk ids (D23)
- Model output JSON: `{ answer, citations: [{ passage, quote }], refused }`, parsed and shape-checked by hand
- Deterministic citation validator: quote ≥ 4 words and verbatim in its chunk after minimal normalisation (D24); invalid citations are flagged in the response
- Three refusal gates (D25): vector similarity < 0.35 (provisional, no model call), model refusal, no valid citation; never an uncited answer
- Errors: retryable failures (timeout, unreachable, 5xx, malformed JSON) retried once, then 503 (D27)
- `POST /ask` and `npm run ask` over the same `AnswerService`
- Tests: 115 unit tests in total, none needing a model or database (LLM mocked by `FakeLlmClient`); HTTP tests for 200 / 400 / 503 / 500; a wiring test for `.env` → `LlmModule` that found a real bug (D22)

**Done when:** `/ask` works end to end against the local model, and the unit tests pass without a model running. ✅ Verified against the running API with llama3.1:8b: cited answer (200), out-of-scope refusal (200), bad body (400), model unreachable (503 after the retry). Known limitation recorded: a real quote can back a wrong answer (D26) — measured in Phase 4.

## Phase 4 — Evaluation — `feat/evaluation`

**Goal:** measured quality, not assumed quality.

- `eval/questions.jsonl`: 40 questions, 30 answerable (with gold article) and 10 unanswerable; mix casual and legal wording (D18 hypothesis); include the two known faithfulness failures from D26
- The agent drafts candidates; **Omri verifies every gold reference against the source text**
- `npm run eval`:
  - Retrieval: hit@5 and MRR for vector vs keyword vs hybrid
  - Answers: faithfulness (LLM judge, fixed rubric), citation-validity rate, refusal accuracy
- Choose top-k and the refusal threshold from these numbers, and write down how
- Results committed under `eval/results/`

**Done when:** the results table exists, comes from a real run, and the chosen threshold is justified in `DECISIONS.md`.

## Phase 5 — CI, docs, polish — `chore/ci-docs-polish`

**Goal:** a finished, defensible repo.

- CI: lint, build, unit tests, integration tests (Postgres service), retrieval eval as a gate (fails if hit@5 drops below the threshold set from the baseline)
- The LLM eval is not part of normal CI (it needs a running model)
- `README.md`: problem, architecture diagram, quickstart, API examples with real responses, results table, limitations, not-legal-advice note
- Quickstart tested from a fresh clone

**Done when:** a fresh clone works with only the documented commands and CI is green.
